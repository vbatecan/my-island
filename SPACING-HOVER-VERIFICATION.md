# Settings, lyric zoom, fullscreen and hover fixes — 2026-11-08

Settings now share 16px page padding on every tab, a 200px wrapped label column, a 16px label/control gap, 32px minimum form rows, and consistent section/action spacing. Native tabs, setting bindings, scrolling, and persistence are preserved. Renderer captures of the Appearance and Behavior pages were reviewed against the reported spacing problem.

Timed lyrics now use a larger 18px current line and smaller 13px previous/next lines. As rows move upward, the incoming line grows and the finished line shrinks into the upper position. Font sizes are rasterized at their actual values, quantized to quarter-pixel base-size steps (21 possible sizes per zoom/DPI), with continuous row movement and fading. This intentionally supersedes the earlier constant-18px optimization to implement the requested zoom effect; RAM was not rebenchmarked for this change. Existing animation speed, interruption, pause/seek, and reduced-motion behavior remain.

Fullscreen detection now considers visible client/surface coverage on the selected monitor, foreground/z-order ownership, and DWM cloaking. Ordinary captioned maximized windows are distinguished from fullscreen surfaces. Show/hide, destroy, minimize and location changes wake the policy; no polling loop was added. Native visibility handling prevents backend show/style updates from resurrecting an overlay while suppression is active. Exclusive D3D fallback is limited to appropriate borderless foreground windows. Generic detection cannot establish compatibility with every game's exclusive display mode.

Normal hover is now derived from the actual native cursor, current window coordinates, visible contour, and window under the pointer. Slint child hover changes and moving local coordinates no longer reset visits. Native leave directly clears hover; release/focus loss clears stale pressed state. Pointer state is reconciled after morph/configuration changes and, through a one-shot event-turn callback, after initial redraw/geometry changes. Dwell timers are re-armed only when the movement deadline actually changes, avoiding starvation from synthetic mouse events generated by region updates. Explicit close, manual panels and pinning preserve their existing semantics. Fullscreen suppression clears transient hover previews/input state.

It uses an isolated overlay profile and its own external temporary WinForms fixture, without resizing existing user applications or changing startup registration. Focus clicks are issued only after verifying that the fixture owns the target point.
- An early actual-cursor hover expansion/contraction run passed. Later repetitions were interrupted by external cursor movement before the configured dwell completed. Edge traces showed hover being cancelled correctly when the cursor departed. The probe now detects this interference and reports **INCONCLUSIVE**, rather than falsely treating it as an app failure. The final all-in-one physical hover repetition was therefore not claimed as a pass. Callback regressions and hover deadline tests passed.

Runtime checks used the primary 1920×1080 display at 96 DPI. Additional physical monitors/DPI scales and real exclusive-fullscreen games remain device checks. Opt-in `--trace-hover` writes only local edge/timer diagnostics; normal operation does not enable that logging. The probe restores the original cursor and closes only its own fixture/overlay processes.
